# План статей по изучению CSS

Цель серии — небольшими итерациями научиться оформлять HTML-страницы, понимать выбор применяемых правил и строить макеты, которые сохраняют удобство при изменении ширины экрана и размера текста.

Каждый пункт с номером — отдельная короткая статья с одной задачей, практикой и проверяемым результатом. Основной маршрут — статьи 1–80. Статьи 81–96 предназначены для дальнейшего углубления.

## Учебное окружение и предварительные знания

- Перед началом нужно уметь создавать HTML-документ, использовать ссылки, изображения, семантические области и подписанные поля формы. Эти темы изучаются по [плану HTML](HTML_PLAN.md).
- Практика продолжает сайт `web-practice` из курса HTML: главная, список статей, отдельная статья и контакты. При отдельном прохождении курса предоставляется готовая исходная разметка.
- Нужны редактор, локальный статический HTTP-сервер и браузер с DevTools. Стили хранятся в `styles.css`; путь подключения проверяется относительно каждой HTML-страницы.
- Начальные упражнения используют обычный CSS без препроцессоров и библиотек. Это позволяет видеть, какое правило создаёт результат.
- Для проверки берутся короткий и длинный текст, несколько изображений и заполненная форма. Макет проверяется при узкой, средней и широкой области просмотра, а также при увеличении масштаба.
- Для возможностей из дополнительных тем указываются проверенные браузеры, поддержка и базовое поведение без улучшения. Проверка `@supports` используется там, где подходит условие поддержки синтаксиса.

Основы изложены в [учебном разделе MDN по CSS](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Styling_basics), а методы размещения элементов — в [разделе о CSS-макетах](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/CSS_layout).

## Как проходить небольшую итерацию

1. Открыть исходную страницу и сформулировать одну задачу оформления.
2. Прочитать объяснение нужного свойства или механизма.
3. Изменить небольшой фрагмент `styles.css` и обновить страницу.
4. Проверить применённое правило и вычисленное значение в DevTools.
5. Изменить длину текста или ширину области просмотра и проверить результат.
6. Повторить приём на другом элементе без готового решения.

Ориентир — 15–25 минут на тему. Если упражнение требует нескольких новых механизмов, оно делится на отдельные занятия.

## Итоговый учебный проект

Адаптивное оформление сайта из курса HTML: общий контейнер, навигация, сетка карточек, текст статьи, таблица и форма контактов.

Критерии готовности:

- Все страницы используют общую таблицу стилей и согласованные компоненты.
- Читатель находит источник применённого значения и объясняет простой конфликт каскада.
- Ширина элемента объясняется его блочной моделью и содержащим блоком.
- Навигация и группы элементов используют Flexbox, сетка карточек — Grid.
- Страница проверена при ширине области просмотра 320, 768 и 1280 CSS-пикселей, а также между этими значениями.
- Изменение текста не ломает высоту карточек; длинные ссылки не расширяют всю страницу.
- Изображения сохраняют пропорции или имеют намеренное кадрирование.
- При масштабе 200% содержание и управление остаются доступными; при эквиваленте 320 CSS-пикселей нет общей горизонтальной прокрутки, кроме областей, которым нужна двумерная раскладка, например таблицы.
- Фокус виден, порядок Tab логичен, нужные действия доступны с клавиатуры.
- Текст имеет проверенный контраст, ошибочное состояние формы сопровождается текстом.
- Настройка уменьшения движения учитывается.
- При отсутствии дополнительной CSS-возможности сохраняется доступ к содержимому.
- Итог проверен как минимум в двух доступных браузерных движках с записью использованных версий.

## Отметки готовности

Чекбокс означает готовность статьи в проекте. Он отмечается после подготовки русской и английской версий, проверки примера в указанных браузерах, разных размеров и нужных состояний, а также сборки, меню и поиска.

Для адаптивных примеров проверяются промежуточные ширины, длинный текст, масштаб и клавиатура. Для дополнительных возможностей указываются поддержка и базовый вариант. Учебный прогресс читателя ведётся отдельно; файлы статей и пункты меню добавляются по мере подготовки материалов.
