# Stackbook

Основа документации на VitePress **2.0.0-alpha.20**. Русский язык по умолчанию (`/`), английский — `/en/`.

Корневые разделы: **Backend (Сервер)**, **Базы данных**, **Инфраструктура**.

## Запуск

Требуются Node.js 22.18+ (или 24+) и pnpm 11.25.0.

```sh
pnpm install --frozen-lockfile
pnpm dev
```

## Запуск через Docker

Для разработки достаточно Docker с Compose. Node.js и pnpm на компьютере не требуются.

```sh
docker compose up --build -d
```

Сайт будет доступен по адресу [http://localhost:5173](http://localhost:5173). Файлы из `docs/` подключаются в контейнер: изменения страниц, переводов и бокового меню подхватываются автоматически. Для Docker Desktop включена проверка изменений файлов через polling.

Зависимости устанавливаются внутри образа; локальный `node_modules` не используется. Кэш VitePress хранится в отдельном Docker-томе.

```sh
docker compose logs -f docs   # Смотреть логи
docker compose down           # Остановить и удалить контейнер
```

Чтобы изменить порт, задайте `STACKBOOK_PORT`, например `STACKBOOK_PORT=4173`, в `.env` в корне проекта и повторите `docker compose up --build -d`.

После изменения `package.json`, `pnpm-lock.yaml`, тестов или Dockerfile повторите запуск с `--build`: в контейнер подключается только папка `docs/`, остальные файлы берутся из образа.

Это режим разработки. Для публикации используйте статическую сборку из раздела «Публикация» ниже.

## Makefile

При установленном `make` доступны сокращённые команды:

```sh
make           # Показать справку
make up        # Собрать образ и запустить сайт в фоне
make down      # Остановить и удалить контейнер
make build     # Собрать Docker-образ без запуска сервиса
make logs      # Смотреть логи
make restart   # Перезапустить сервис
make shell     # Открыть sh в работающем контейнере
make check     # TypeScript, тесты и сборка сайта во временном контейнере
```

`make check` собирает актуальный образ и запускает временный контейнер. Результат сборки сайта появится в `docs/.vitepress/dist/`. `make` без аргументов ничего не запускает, кроме вывода справки. На Windows без `make` используйте команды `docker compose` напрямую.

## Проверка и сборка

```sh
pnpm check    # TypeScript, тесты поиска и сборка
pnpm build    # Результат: docs/.vitepress/dist/
pnpm preview  # Просмотр собранного сайта
```

## Настройки

- `docs/.vitepress/config.ts` — название, языки и параметры сайта.
- `docs/.vitepress/navigation.ts` — главное меню.
- `docs/.vitepress/sidebar.ts` — автоматическое боковое меню по папкам и Markdown-файлам.
- `docs/.vitepress/search.ts` — локальный поиск по заголовкам и тексту.
- `docs/.vitepress/theme/` — оформление и подключение поискового анализатора в браузере.
- `docs/index.md` — главная; `docs/backend/`, `docs/databases/`, `docs/infrastructure/` — разделы.
- `docs/en/` — английские версии с такими же путями.

Поиск не требует API-ключей. Он учитывает русские и английские словоформы, регистр, е/ё, начало слова и опечатки в словах длиннее четырёх символов. Индексы разделены по языкам; открытие поиска — Ctrl+K / ⌘K. Обработчик поиска должен подключаться и в конфиге, и в теме.

## Дата обновления статьи

Внизу страниц документации автоматически выводятся дата и время последнего коммита соответствующего Markdown-файла. Подписи — «Последнее обновление» на русском и «Last updated» на английском. Формат даты соответствует языку страницы, время отображается в часовом поясе браузера читателя.

Новый файл должен хотя бы один раз попасть в коммит: до этого даты в Git нет и строка не отображается. Незакоммиченные правки не меняют время последнего обновления. Дата проверки данных, указанная в тексте статьи, остаётся отдельной отметкой.

При сборке в GitHub Actions история загружается полностью (`fetch-depth: 0` у `actions/checkout`), чтобы время определялось по последнему изменению каждой статьи. Подробнее: [Last Updated в VitePress](https://vitepress.dev/reference/default-theme-last-updated).

## Боковое меню

Меню строится автоматически из `docs/` для русского языка и `docs/en/` для английского. Добавьте папку или `.md`-файл — вручную прописывать боковое меню не требуется. При `pnpm dev` оно обновляется после добавления, удаления, переименования страниц и изменения их подписей.

Поддерживаются **6 уровней, включая корневой** — максимум стандартной темы VitePress. Более глубокие пункты в меню не выводятся.

`index.md` задаёт страницу и название своей папки. Отдельным дочерним пунктом он не дублируется. Папка без `index.md` становится группой, если в ней есть доступные материалы. Главная страница, `404.md`, служебные каталоги, скрытые файлы и имена, начинающиеся с `_`, в меню не попадают.

Подпись берётся из `sidebarLabel`, затем `title` во frontmatter, затем первого заголовка `#`, затем имени файла или папки. Порядок — по именам с естественной сортировкой чисел; для ручного порядка задайте число `sidebarOrder`. Подписи и порядок папки задаются в её `index.md`.

```yaml
---
title: Серверная разработка
sidebarLabel: Backend (Сервер)
sidebarOrder: 1
---
```

Сохраняйте одинаковые пути в обеих языковых версиях, чтобы переключение языка вело на соответствующую страницу.

## Публикация

Разместите содержимое `docs/.vitepress/dist/` на статическом хостинге. Базовый путь задаётся переменной `VITEPRESS_BASE` до сборки, по умолчанию `/`. Для подкаталога используйте, например, `/stackbook/`.

По умолчанию включён `cleanUrls`: хостинг должен отдавать `.html` для адресов без расширения. При `GITHUB_PAGES=true` сборка использует явные `.html`-ссылки.

## GitHub Pages через GitHub Actions

Workflow `.github/workflows/deploy-pages.yml` проверяет проект, собирает сайт и публикует его в GitHub Pages после push в `master`. Также доступен ручной запуск через **Actions → Deploy Stackbook to GitHub Pages → Run workflow**.

Для первого запуска:

1. В репозитории откройте **Settings → Pages**.
2. В **Build and deployment → Source** выберите **GitHub Actions**.
3. Сохраните изменения проекта в Git и отправьте их в `master`.
4. Дождитесь успешного выполнения workflow. Адрес будет показан в задании `deploy` и настройках Pages.

Для текущего репозитория стандартный адрес после публикации — [https://lexusalex.github.io/stackbook/](https://lexusalex.github.io/stackbook/). Если переименуете основную ветку, измените `on.push.branches` в workflow.

Workflow использует Node.js 24, версию pnpm из `package.json`, lockfile и кэш зависимостей. Перед публикацией выполняется `pnpm check`. Персональные токены и дополнительные секреты не требуются: используется встроенный `GITHUB_TOKEN`.

Базовый путь берётся из `actions/configure-pages`: для проекта это `/stackbook/`, для сайта пользователя или настроенного собственного домена — `/`. Путь не нужно прописывать вручную. В Pages-сборке отключены чистые URL, поэтому прямое открытие вложенных статей использует `.html`.

Чтобы проверить такую сборку локально в PowerShell:

```powershell
$env:GITHUB_PAGES = 'true'
$env:VITEPRESS_BASE = '/stackbook/'
pnpm build
pnpm preview
```

После запуска предпросмотра откройте адрес с префиксом `/stackbook/`. Для возврата к обычной локальной сборке удалите переменные в этой сессии:

```powershell
Remove-Item Env:GITHUB_PAGES, Env:VITEPRESS_BASE -ErrorAction SilentlyContinue
```

Подробнее: [публикация VitePress на GitHub Pages](https://vitepress.dev/guide/deploy#github-pages) и [настройка workflows Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).
