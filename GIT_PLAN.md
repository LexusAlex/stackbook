# План статей по изучению Git

Цель серии — небольшими итерациями освоить сохранение изменений, чтение истории, работу с ветками и совместную разработку, затем научиться исправлять типичные ошибки с пониманием состояния репозитория.

Каждый пункт с номером — отдельная короткая статья с одной задачей, практикой и проверяемым результатом. Разделы объединяют связанные темы; следующие задания продолжают один учебный проект.

Основной маршрут — статьи 1–75. Статьи 76–99 — дополнительные инструменты, углубление и работа с выбранным хостингом. Знакомую тему можно проходить через проверочное задание.

## Учебное окружение

- Отдельный каталог git-practice с небольшим текстовым проектом: README, несколько заметок и простой файл настроек-примера.
- Для совместной работы — отдельный локальный bare-репозиторий и два клона, имитирующие двух участников. Такой стенд позволяет изучить fetch, push и конфликты до настройки внешнего сервиса.
- Примеры явно указывают используемую оболочку: PowerShell или Bash. Файловые пути и создание тестовых файлов соответствуют этой оболочке.
- Начальная ветка имеет заранее выбранное имя; main в примерах означает фактическое имя ветки учебного проекта.
- Для переключения веток используется git switch, для восстановления файлов — git restore. Перед началом проверяются установленная версия Git и доступность нужных параметров.
- Упражнения с отменой и переписыванием выполняются на искусственных учебных изменениях. Перед командой фиксируются состояние рабочего каталога, индекс и положение веток; после неё проверяются все затронутые части.

Порядок тем составлен с опорой на [Pro Git](https://git-scm.com/book/en/v2). Различия восстановления файлов, перемещения ветки и отменяющего коммита сверяются с официальными руководствами [restore](https://git-scm.com/docs/git-restore), [reset](https://git-scm.com/docs/git-reset) и [revert](https://git-scm.com/docs/git-revert).

## Как проходить небольшую итерацию

1. Прочитать краткое объяснение одной задачи.
2. Посмотреть исходное состояние через status, подходящий diff или граф истории.
3. Выполнить минимальное действие на учебном проекте.
4. Проверить содержимое файлов, индекс и историю там, где команда их затрагивает.
5. Объяснить своими словами, что изменилось и что осталось в прежнем состоянии.
6. Повторить задачу с другим учебным файлом или небольшой ошибкой.

Ориентир — 15–25 минут на первоначальное знакомство и отдельное повторение. Если тема требует нескольких самостоятельных задач, материал делится на более короткие занятия.

## Основной маршрут

### 1. Первое знакомство и настройка

- [ ] **1. Зачем нужен контроль версий** — история изменений, снимок проекта и возврат к сохранённому состоянию. Результат: понятно, какую задачу Git решает при работе над проектом.
- [ ] **2. Git и сервисы размещения репозиториев** — локальный Git, серверный репозиторий и интерфейс GitHub или GitLab. Результат: различаются коммит на своём компьютере и публикация на сервере.
- [ ] **3. Установка Git** — установка для своей ОС и проверка git --version. Результат: Git доступен в выбранном терминале.
- [ ] **4. Терминал для учебных примеров** — текущий каталог, пути и используемая оболочка. Результат: создан и найден отдельный каталог учебного проекта.
- [ ] **5. Имя и почта автора** — user.name, user.email и отличие авторства коммита от авторизации на сервере. Результат: новые учебные коммиты получают ожидаемые данные автора.
- [ ] **6. Области конфигурации** — локальные, глобальные и системные настройки, просмотр источника значения. Результат: понятно, какая настройка действует в учебном репозитории.
- [ ] **7. Редактор сообщений Git** — выбор редактора, сохранение сообщения и выход. Результат: проверено открытие и завершение редактирования сообщения.
- [ ] **8. Создание репозитория** — git init, каталог .git и выбор имени начальной ветки. Результат: учебный каталог стал репозиторием с явно выбранной начальной веткой.

### 2. Первый коммит и повседневные изменения

- [ ] **9. Рабочий каталог, индекс и коммит** — три состояния содержимого и роль подготовки к коммиту. Результат: читатель объясняет, откуда берётся содержимое следующего коммита.
- [ ] **10. Состояние репозитория** — git status, отслеживаемые и неотслеживаемые файлы. Результат: определено, какие изменения уже подготовлены, а какие ещё нет.
- [ ] **11. Добавление файла в индекс** — git add с явным путём и проверка результата. Результат: в индекс попал только нужный новый файл.
- [ ] **12. Первый коммит** — git commit и проверка записанного снимка. Результат: создан первый коммит с учебным файлом.
- [ ] **13. Неподготовленные изменения** — git diff между рабочим каталогом и индексом. Результат: найдены правки, которые пока не войдут в коммит.
- [ ] **14. Подготовленные изменения** — git diff --staged между индексом и текущим коммитом. Результат: проверено точное содержимое будущего коммита.
- [ ] **15. Повторное изменение файла** — редактирование после git add и повторная подготовка. Результат: объяснено, почему коммит может содержать предыдущий вариант файла.
- [ ] **16. Добавление части изменений** — git add -p и выбор отдельных фрагментов. Результат: в коммит включена одна задача из нескольких правок файла.
- [ ] **17. Одна задача в одном коммите** — разделение независимых изменений и проверка каждого снимка. Результат: две небольшие задачи сохранены отдельными понятными коммитами.
- [ ] **18. Сообщение коммита** — краткое описание результата и пояснение причины при необходимости. Результат: сообщение понятно человеку, который не участвовал в работе.
- [ ] **19. Переименование файла** — git mv и распознавание перемещения по изменениям содержимого. Результат: переименование сохранено и прослеживается в истории.
- [ ] **20. Удаление отслеживаемого файла** — git rm, подготовленное удаление и коммит. Результат: удаление записано в истории, прежнее содержимое остаётся доступным в старом коммите.

### 3. Чтение истории

- [ ] **21. История коммитов** — git log, краткий формат и ограничение количества записей. Результат: найден коммит по сообщению и автору.
- [ ] **22. Содержимое одного коммита** — git show, сведения о коммите и его изменения. Результат: объяснено, что изменил выбранный коммит.
- [ ] **23. Сравнение двух версий** — git diff между двумя коммитами и порядок аргументов. Результат: получен и правильно прочитан список изменений между версиями.
- [ ] **24. История отдельного файла** — ограничение log путём и просмотр изменений файла. Результат: найдено изменение конкретной строки учебного документа.
- [ ] **25. HEAD и ссылки на предков** — текущий коммит, родитель, HEAD~1 и идентификатор коммита. Результат: выбрана нужная версия без поиска по порядковому номеру в списке.

### 4. Состав репозитория и переносимость

- [ ] **26. Правила .gitignore** — шаблоны для локальных настроек, временных файлов и результатов сборки. Результат: неотслеживаемые служебные файлы исключены из обычного списка изменений.
- [ ] **27. Прекращение отслеживания файла** — git rm --cached и сохранение локального файла. Результат: файл остаётся на диске, но его удаление из репозитория подготовлено.
- [ ] **28. Почему файл игнорируется** — git check-ignore -v и поиск сработавшего правила. Результат: найдено конкретное правило, скрывающее учебный файл.
- [ ] **29. Переводы строк через .gitattributes** — LF, CRLF и политика для текстовых файлов проекта. Результат: поведение учебного текста проверено без случайной массовой замены строк в проекте.

### 5. Исправление небольших ошибок

- [ ] **30. Убрать файл из индекса** — git restore --staged и сохранение правок в рабочем каталоге. Результат: случайно подготовленный файл исключён из будущего коммита без потери редактирования.
- [ ] **31. Отменить правки рабочего файла** — git restore, источник по умолчанию и предварительный просмотр diff. Результат: учебный файл возвращён к состоянию индекса, последствия для незакоммиченных правок объяснены.
- [ ] **32. Взять файл из старого коммита** — git restore --source с явным путём. Результат: нужный старый вариант файла восстановлен как изменение для нового коммита.
- [ ] **33. Исправить последний локальный коммит** — git commit --amend и замена идентификатора коммита. Результат: сообщение или состав ещё не опубликованного учебного коммита исправлен.
- [ ] **34. Отменить коммит новым коммитом** — git revert и сохранение существующей истории. Результат: нежелательное изменение отменено отдельным коммитом, который можно передать другим участникам.

### 6. Ветки и слияние

- [ ] **35. Что такое ветка** — ссылка на коммит, текущая ветка и её движение при коммите. Результат: по схеме истории определено положение двух веток.
- [ ] **36. Создание ветки** — git switch -c и имя для небольшой задачи. Результат: новая задача начата в отдельной ветке.
- [ ] **37. Переключение веток** — git switch, состояние рабочего каталога и препятствующие переключению правки. Результат: переключение выполнено с пониманием судьбы локальных изменений.
- [ ] **38. Независимые изменения в ветках** — разные коммиты от общей исходной точки. Результат: созданы две линии работы и объяснена их связь.
- [ ] **39. Слияние fast-forward** — перемещение ссылки без отдельного коммита слияния. Результат: линейная ветка задачи включена в основную ветку.
- [ ] **40. Коммит слияния** — git merge, разошедшаяся история и два родителя merge-коммита. Результат: изменения двух веток объединены с понятной формой истории.
- [ ] **41. Как возникает конфликт** — конкурирующие правки одного участка и маркеры конфликта. Результат: конфликт намеренно воспроизведён и найдены оба варианта.
- [ ] **42. Решение конфликта слияния** — редактирование итогового текста, git add и завершение merge. Результат: нужное содержимое сохранено, маркеры удалены и результат проверен.
- [ ] **43. Отмена незавершённого слияния** — git merge --abort на заранее подготовленном чистом учебном состоянии. Результат: учебное слияние отменено, состояние ветки проверено.
- [ ] **44. Удаление локальной ветки** — проверка включённых коммитов и git branch -d. Результат: завершённая ветка удалена без удаления её истории из основной ветки.
- [ ] **45. Отсоединённый HEAD** — просмотр старого коммита и создание ветки для продолжения работы. Результат: учебный коммит из detached HEAD сохранён доступной веткой.

### 7. Удалённый репозиторий и два участника

- [ ] **46. Локальный серверный репозиторий** — bare-репозиторий без рабочего каталога и согласованное имя начальной ветки. Результат: создан отдельный учебный репозиторий для обмена изменениями.
- [ ] **47. Адреса remote** — git remote add, просмотр через git remote -v, имя origin и адрес репозитория. Результат: первый учебный проект связан с серверным репозиторием.
- [ ] **48. Первая отправка ветки** — git push, явная ветка и настройка upstream. Результат: ветка опубликована в учебном серверном репозитории.
- [ ] **49. Клонирование репозитория** — git clone, рабочая копия и связь с источником. Результат: подготовлен второй клон с уже опубликованной историей для имитации другого участника.
- [ ] **50. Получение изменений через fetch** — обновление локальных сведений после коммита и отправки из второго клона. Результат: новый коммит другого участника получен без изменения собственной рабочей ветки.
- [ ] **51. Remote-tracking ветки** — origin/main или другое фактическое имя ветки и отличие от локальной ветки. Результат: объяснено, какие данные являются последним известным состоянием сервера.
- [ ] **52. Опережение и отставание ветки** — ahead, behind и актуальность сведений после fetch. Результат: по графу и состоянию определены отсутствующие с каждой стороны коммиты.
- [ ] **53. Включение полученных изменений** — явное слияние remote-tracking ветки после fetch. Результат: коммит второго участника включён в рабочую ветку.
- [ ] **54. Обновление через pull --ff-only** — fetch с последующим fast-forward и отказ при разошедшейся истории. Результат: обычное обновление выполнено, ситуация расхождения распознана.
- [ ] **55. Отказ push из-за новых коммитов** — non-fast-forward, получение истории и согласование изменений. Результат: отправка выполнена после включения работы другого участника.
- [ ] **56. Удаление ветки на сервере** — проверка завершённой задачи и git push --delete. Результат: ненужная учебная ветка удалена из серверного репозитория.
- [ ] **57. Очистка устаревших ссылок remote** — git fetch --prune и отличие ссылки от локальной рабочей ветки. Результат: удалённая на сервере ветка исчезла из актуальных remote-tracking ссылок.

### 8. Незавершённая работа и перенос коммитов

- [ ] **58. Сохранение работы через stash** — git stash push, сообщение и отдельное включение неотслеживаемых файлов через -u. Результат: учебные правки временно сохранены, состав сохранения проверен.
- [ ] **59. Возврат сохранённой работы** — stash list, show, apply, pop и удаление проверенной записи. Результат: возвращены нужные правки и объяснено, сохраняется ли запись stash.
- [ ] **60. Конфликт при возврате stash** — разбор конфликтующих изменений и сохранность записи при неудачном pop. Результат: нужный текст восстановлен, итог и оставшиеся записи проверены.
- [ ] **61. Перебазирование личной ветки** — git rebase, новая основа и новые идентификаторы коммитов. Результат: ещё не опубликованные учебные коммиты перенесены на обновлённую основную ветку.
- [ ] **62. Конфликт при rebase** — остановка на конкретном коммите, исправление, add и --continue. Результат: перебазирование завершено с проверкой каждого затронутого изменения.
- [ ] **63. Отмена незавершённого rebase** — git rebase --abort и состояние до начала операции. Результат: учебная ветка возвращена к исходной истории.
- [ ] **64. Когда выбрать merge или rebase** — форма истории и договорённость команды о сохранении или переписывании коммитов. Результат: для двух учебных ситуаций выбран и объяснён подход.

### 9. Перемещение ветки и восстановление истории

- [ ] **65. Reset --soft** — перемещение текущей ветки с сохранением индекса и рабочего каталога. Результат: последний локальный учебный коммит разобран на подготовленные изменения.
- [ ] **66. Reset --mixed** — перемещение ветки и сброс индекса при сохранении рабочих файлов. Результат: учебные изменения готовы к повторному разделению на коммиты.
- [ ] **67. Выбор restore, reset или revert** — восстановление файла, перемещение ветки и отменяющий коммит. Результат: для нескольких ошибок выбрана команда с объяснением её действия на историю и файлы.
- [ ] **68. Восстановление через reflog** — локальная история перемещения ссылок и её ограничения. Результат: найден ранее созданный учебный коммит и закреплён новой веткой.

### 10. Метки и совместный рабочий процесс

- [ ] **69. Лёгкая метка** — git tag и обозначение выбранного коммита. Результат: учебная версия отмечена именем и найдена по нему.
- [ ] **70. Аннотированная метка** — сообщение метки и отличие от лёгкой ссылки. Результат: подготовлена метка учебного релиза с описанием.
- [ ] **71. Публикация метки** — отдельная отправка конкретного тега и получение во втором клоне. Результат: оба участника могут найти один и тот же учебный релиз.
- [ ] **72. Самопроверка перед отправкой** — состав коммитов, итоговый diff и проверка результата задачи. Результат: в ветке нет случайно включённых файлов или посторонних изменений.
- [ ] **73. Задача в отдельной ветке** — последовательность обновления основы, работы, проверки и публикации. Результат: небольшая задача полностью пройдена в учебном проекте.
- [ ] **74. Исправление по замечанию участника** — просмотр чужой ветки во втором клоне и дополнительный коммит. Результат: замечание отражено отдельной проверенной правкой.
- [ ] **75. Итоговая работа с двумя клонами** — коммиты, обмен, конфликт, отмена ошибочного изменения и метка. Результат: все проверки учебного проекта выполнены, история объяснена по графу.

## Итоговый учебный проект

Небольшой текстовый проект, общий учебный bare-репозиторий и два независимых клона.

Критерии готовности:

- Настройки автора проверены, начальная ветка имеет понятное имя.
- Изменения сохраняются небольшими коммитами после проверки их точного состава.
- Локальные служебные файлы исключены из отслеживания по выбранной политике.
- По истории можно найти изменение и сравнить две версии.
- Отдельная задача выполнена в ветке и включена в основную ветку.
- Два участника обмениваются коммитами через fetch и push.
- Намеренный конфликт решён с проверкой итогового содержимого.
- Незавершённая работа сохранена и возвращена через stash.
- Ошибочный коммит отменён новым коммитом.
- Ранее созданный учебный коммит найден через reflog и сохранён веткой.
- Итоговая версия отмечена меткой и получена во втором клоне.
- По графу объяснено происхождение коммитов и состояние каждой рабочей ветки.

## Формат каждой статьи

1. Одна задача и ожидаемый результат.
2. Предварительные условия и ссылки на нужные предыдущие материалы.
3. Короткое объяснение команды и затрагиваемых частей репозитория.
4. Исходное состояние: файлы, индекс и история в необходимом для задачи объёме.
5. Минимальные команды с явными путями, именами веток и выбранной оболочкой.
6. Проверка результата и объяснение изменений.
7. Типичная ошибка и способ вернуться к подходящему учебному состоянию.
8. Небольшое самостоятельное задание с признаками правильного результата.

Для отменяющих команд отдельно объясняется судьба незакоммиченных файлов и уже созданных коммитов. Для действий с remote показывается состояние обеих сторон.

Материал заканчивается проверкой достигнутого результата. Переходы между опубликованными статьями доступны через меню и навигацию сайта.
