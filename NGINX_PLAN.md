# План статей по Nginx

Цель серии — небольшими итерациями пройти от установки Nginx до сайта с доменом и HTTPS, затем подключить приложение за обратным прокси. Основные примеры рассчитаны на Ubuntu/Debian.

Одна итерация — одна короткая статья с конкретным, проверяемым результатом. Каждая следующая статья продолжает конфигурацию из предыдущей.

## Готово

- [x] **Версии** — нумерация релизов, различия mainline и stable, выбор ветки, версии пакетов и Docker-теги. Статьи: [русская](docs/infrastructure/servers/nginx/versions.md) и [английская](docs/en/infrastructure/servers/nginx/versions.md).

## Порядок статей

| № | Статья | Что разобрать | Результат итерации |
| --- | --- | --- | --- |
| 1 | Установка Nginx | Выбор ветки и источника пакета, подключение официального репозитория, установка, проверка через `nginx -v` и `nginx -V` | Установлен пакет выбранной ветки, известны его версия и источник |
| 2 | Запуск и автозагрузка | Управление сервисом через systemd, статус, запуск и остановка, включение автозагрузки | Nginx работает и запускается после перезагрузки сервера |
| 3 | Доступ по IP | Проверка HTTP локально и извне, прослушиваемый адрес и порт, правила межсетевого экрана | Стартовая страница доступна с другого компьютера |
| 4 | Устройство конфигурации | `nginx.conf`, `include`, контексты `http`, `server`, `location`, просмотр полной конфигурации через `nginx -T` | Понятно, какой файл редактировать и как он подключается |
| 5 | Первый собственный сайт | Каталог сайта и права чтения, `listen`, `server_name`, `root`, `index`, стандартный сайт из пакета | Nginx отдаёт собственную HTML-страницу из отдельного каталога |
| 6 | Применение изменений | Проверка через `nginx -t`, reload и restart, исправление ошибочной конфигурации | Изменения применяются после проверки без лишнего перезапуска сервиса |
| 7 | Пути и файлы | Выбор `location`, сопоставление URI с `root`, `index`, `try_files`, ответ для отсутствующего файла | Страницы и ресурсы отдаются по ожидаемым адресам, отсутствующие файлы возвращают 404 |
| 8 | Подключение домена | DNS-записи A и при необходимости AAAA, `server_name`, проверка разрешения имени и HTTP-ответа | Сайт открывается по доменному имени |
| 9 | Подключение HTTPS | Получение сертификата Let's Encrypt через ACME-клиент, подключение сертификата и ключа, проверка HTTPS | Сайт открывается по HTTPS с доверенным сертификатом |
| 10 | Продление сертификата и редирект | Автоматическое продление, проверочный запуск продления, применение обновлённого сертификата, перенаправление HTTP на HTTPS | Продление проверено, HTTP-запросы перенаправляются на HTTPS |
| 11 | Проксирование приложения | Приложение на локальном порту, `proxy_pass`, передача Host и сведений о клиенте и схеме запроса, доверие к прокси на стороне приложения | Nginx принимает внешние запросы по HTTPS и передаёт их работающему backend |
| 12 | Диагностика | `access.log`, `error.log`, журнал сервиса, последовательная проверка причин 403, 404, 502 и 504 | По логам можно отличить ошибку доступа или пути от недоступности и таймаута backend |

## Формат каждой статьи

1. Задача и ожидаемый результат.
2. Предварительные условия: что должно быть готово после предыдущей итерации.
3. Краткое объяснение нужных понятий.
4. Минимальные команды и изменения конфигурации с путями файлов.
5. Проверка результата и ожидаемый ответ.
6. Типичные ошибки и способы найти причину.
7. Ссылки на готовые связанные материалы без анонсов будущих статей.
