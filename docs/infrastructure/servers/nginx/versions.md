# Версии

**Проверено 24 октября 2026 года.** Статья описывает NGINX Open Source. Номера ниже — снимок на эту дату, а не автоматически обновляемый список.

## Актуальные ветки

| Ветка | Последний релиз | Дата релиза |
| --- | --- | --- |
| **Mainline** — `1.31.x` | `1.31.8` | 21 октября 2026 |
| **Stable** — `1.30.x` | `1.30.6` | 14 октября 2026 |

Ветка `1.28.x` уже находится в разделе **Legacy versions**. Доступность старого архива на сайте не делает его текущей stable-веткой. Актуальные номера сверяйте со [страницей загрузки](https://nginx.org/en/download.html), даты — с журналами [mainline](https://nginx.org/en/CHANGES) и [stable 1.30](https://nginx.org/en/CHANGES-1.30).

## Как читать номер

На примере `1.30.6`:

| Компонент | Значение |
| --- | --- |
| `1` | Основная серия версий |
| `30` | Ветка разработки и сопровождения |
| `6` | Номер релиза внутри этой ветки |

Тип ветки определяется **вторым числом**: нечётное означает mainline (`1.31.x`), чётное — stable (`1.30.x`). Чётность последнего числа на тип ветки не влияет. Это правило описано в [официальной документации по версиям](https://docs.nginx.com/nginx/admin-guide/installing-nginx/installing-nginx-open-source/#stable-and-mainline-versions).

::: info Последнее число не означает «только исправления»
В mainline новые возможности могут появляться при изменении третьего числа: например, `1.31.5` добавила control API и модуль обработки JSON. Поэтому нельзя переносить на Nginx ожидание «patch-релиз никогда не меняет функциональность». Это вывод из [журнала изменений mainline](https://nginx.org/en/CHANGES); перед обновлением читайте изменения конкретного релиза.
:::

## Mainline и stable

**Mainline** — основная линия развития. В неё поступают новые возможности, изменения поведения и исправления. **Stable** получает выбранные критические исправления из mainline; её набор возможностей меняется меньше. Название stable не означает отсутствие ошибок. Различие веток описано в [репозитории Nginx](https://github.com/nginx/nginx#stable-and-mainline-binaries).

Mainline предназначена и для рабочего окружения: официальное руководство рекомендует её для production, а stable — когда особенно важна стабильность набора изменений. Поэтому выбирать stable только из опасения, что mainline является бетой, не требуется. [Рекомендации NGINX](https://docs.nginx.com/nginx/admin-guide/installing-nginx/installing-nginx-open-source/#mainline-version).

При выборе обновления проверяйте также [security advisories](https://nginx.org/en/security_advisories.html): там указаны затронутые версии и релизы с исправлением. Само слово stable не подтверждает наличие всех исправлений безопасности в установленном пакете.

## Как появляются новые ветки

Стабильная ветка фиксирует развитие предыдущей mainline, затем работа продолжается в следующей нечётной ветке. Пример текущего цикла:

```text
1.29.x — предыдущая mainline
   └── 1.30.0 — новая stable, 14 апреля 2026

1.31.0 — следующая mainline, 13 мая 2026
```

Согласно [официальным объявлениям за 2026 год](https://nginx.org/2026.html), `1.30.0` вобрала возможности и исправления `1.29.x`. Переход на другую ветку меняет второе число; очередное обновление внутри выбранной ветки — третье.

## Версия Nginx, пакет и Docker-тег

Это разные идентификаторы. В официальных Linux-репозиториях отдельно выбираются [каналы stable и mainline](https://nginx.org/en/linux_packages.html). Версия пакетной сборки может содержать дополнительные суффиксы: при разборе обновления учитывайте источник пакета и его журнал изменений, а не только первые три числа.

Для официального Docker-образа на дату проверки:

| Тег | На что указывает |
| --- | --- |
| `nginx:mainline`, `nginx:latest` | Текущая mainline — `1.31.8` |
| `nginx:stable` | Текущая stable — `1.30.6` |
| `nginx:1.31`, `nginx:1.30` | Текущий релиз указанной ветки |
| `nginx:1.31.8`, `nginx:1.30.6` | Указанная версия Nginx |
| Суффикс `-alpine` | Вариант образа на Alpine Linux |

Соответствие тегов опубликовано в [манифесте официального образа](https://github.com/docker-library/official-images/blob/master/library/nginx). `latest` здесь относится к mainline.

Теги являются изменяемыми ссылками: полный номер фиксирует версию Nginx, но не неизменность всех слоёв образа. Для воспроизводимого развёртывания фиксируют [digest образа](https://docs.docker.com/dhi/core-concepts/digests/).

## Как посмотреть установленную версию

```sh
nginx -v
nginx -V
```

`-v` выводит версию доступного бинарного файла, `-V` дополнительно показывает компилятор и параметры сборки. Это помогает различать сборки с одинаковым номером Nginx. Описание параметров: [Command-line parameters](https://nginx.org/en/docs/switches.html).
