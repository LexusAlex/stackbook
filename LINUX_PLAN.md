# План статей по изучению Linux

Цель серии — небольшими итерациями освоить терминал, работу с файлами, пользователями, процессами и сетью, затем самостоятельно настроить и обслуживать учебный Linux-сервер.

Каждый пункт с номером — отдельная короткая статья об одном понятии, приёме или задаче. У статьи есть собственная практика и проверяемый результат. Разделы объединяют связанные материалы, а следующие задания продолжают один учебный стенд.

Основной маршрут — статьи 1–108. Статьи 109–131 — дополнительные инструменты и направления углубления. Знакомые темы можно проходить через проверочное задание.

## Учебное окружение

- Основной стенд — виртуальная машина с поддерживаемой Ubuntu Server, Bash, APT и systemd. В установочной статье подготавливаются также man и nano.
- Общие команды отрабатываются и на Debian; особенности установщика, сетевой настройки и служб обозначаются в соответствующих статьях. Статья о Netplan относится к Ubuntu.
- Практика с разметкой и файловыми системами использует отдельный виртуальный диск. Для базовых статей о монтировании файловая система на нём заранее подготовлена; её самостоятельное создание разбирается отдельно.
- Альтернативное окружение для части команд терминала — WSL 2. Его особенности разбираются в дополнительной статье; итоговые проверки сервера выполняются на основной VM.
- Учебный каталог в домашней директории используется для первых упражнений с файлами. Позже появляется отдельный пользователь и каталог данных HTTP-сервиса.

Примеры ориентируются на [документацию Ubuntu Server](https://ubuntu.com/server/docs/) и [Debian Reference](https://www.debian.org/doc/manuals/debian-reference/). Доступность параметров проверяется по установленной версии утилиты; отличия от текущего онлайн-руководства отмечаются в статье.

## Итоговый учебный проект

Одна виртуальная машина с учебным HTTP-сервисом на Python из пакета дистрибутива. Сервис публикует файлы из выделенного каталога, работает от отдельного непривилегированного пользователя и управляется systemd.

Критерии готовности:

- Пользователь входит на сервер по SSH-ключу; доступ проверен в новом сеансе.
- Каталоги сервиса имеют понятного владельца и необходимые права.
- Сервис запускается после перезагрузки VM.
- Локальный HTTP-запрос и запрос с хоста получают ожидаемый ответ.
- В правилах firewall разрешены нужные учебные подключения.
- По процессам, сокетам и журналу можно определить состояние сервиса.
- Сценарий создаёт проверяемую резервную копию каталога, задача запускается по systemd timer.
- Копия восстанавливается в отдельный каталог; содержимое, права и работа сервиса проверены.
- Намеренно внесённые ошибки доступа, запуска и подключения найдены и исправлены.
