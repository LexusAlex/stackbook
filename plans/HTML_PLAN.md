# План статей по изучению HTML

Цель серии — небольшими итерациями научиться создавать понятную структуру веб-страниц: размечать текст, связывать страницы, добавлять изображения, таблицы и доступные формы.

Каждый пункт с номером — отдельная короткая статья с одной задачей, практикой и проверяемым результатом. Основной маршрут — статьи 1–64. Статьи 65–80 расширяют возможности разметки после освоения основ.

## Учебное окружение и связь с другими курсами

- Текстовый редактор, браузер с инструментами разработчика и каталог `web-practice`. Vim можно использовать после первых занятий из [плана Vim](VIM_PLAN.md), но он не является обязательным условием.
- Учебный проект — небольшой сайт о личном учебном проекте: `index.html`, `articles.html`, `contacts.html` и каталог `images`. Остальные ресурсы добавляются по мере необходимости.
- Начальные страницы открываются локально. Перед упражнениями с отправкой формы настраивается локальный статический HTTP-сервер с явными командами запуска и остановки для выбранной среды.
- Основной маршрут использует возможности HTML и браузера. CSS изучается отдельно по [плану CSS](CSS_PLAN.md); программирование на JavaScript и серверная обработка данных требуют отдельных занятий.
- Примеры форм отправляют вымышленные учебные значения через GET на страницу своего локального сайта. Это позволяет увидеть запрос; статический сервер не сохраняет обращения и не отправляет письма.
- Изображения и короткие медиафайлы для упражнений предоставляются вместе с исходными примерами.

Для изучения структуры используется [учебный раздел MDN по HTML](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Structuring_content). Точное назначение элементов и правила вложенности проверяются по [HTML Living Standard](https://html.spec.whatwg.org/multipage/).

## Как проходить небольшую итерацию

1. Прочитать назначение одного элемента или приёма.
2. Открыть исходный файл из предыдущего упражнения.
3. Добавить небольшой фрагмент разметки и сохранить файл.
4. Обновить страницу в браузере и проверить ожидаемое поведение.
5. Посмотреть структуру в инструментах разработчика; для интерактивных элементов проверить клавиатуру.
6. Выполнить похожее задание без готового фрагмента.

Ориентир — 10–20 минут на тему. Важен смысл разметки и проверяемое поведение; оформление развивается в курсе CSS.

## Итоговый учебный проект

Небольшой сайт из главной страницы, списка статей, отдельной статьи и страницы контактов. Он становится исходным материалом для курса CSS.

Критерии готовности:

- У страниц указаны язык, кодировка и разные осмысленные названия.
- Заголовки отражают структуру текста; основные области размечены по смыслу.
- Меню связывает страницы, якорные ссылки ведут в нужные разделы.
- Изображения имеют подходящие текстовые альтернативы и размеры.
- Для видео доступны субтитры, для аудио — текстовая расшифровка.
- Таблица имеет название и связанные с данными заголовки.
- У полей формы есть подписи, имена и подходящие типы.
- Учебная форма проверена с допустимыми и ошибочными значениями; её запрос найден в Network.
- Ссылки, элементы формы и раскрываемые блоки работают с клавиатуры.
- Разметка проверена валидатором, отсутствующие локальные ресурсы исправлены.
- Содержание читается и остаётся логичным без пользовательских стилей.

## Формат каждой статьи

1. Одна задача и ожидаемый результат.
2. Нужный исходный файл и предварительные знания.
3. Краткое объяснение назначения элемента или атрибута.
4. Минимальная правка с понятным контекстом вставки.
5. Проверка в браузере и при необходимости в DevTools.
6. Типичная ошибка, её проявление и исправление.
7. Самостоятельное задание с признаками правильного результата.

Доступность проверяется вместе с соответствующей темой: подписи — при работе с полями, клавиатура — при добавлении интерактивного элемента. Материал заканчивается проверкой результата; переходы между статьями доступны через меню сайта.

## Отметки готовности

Чекбокс означает готовность статьи в проекте. Он отмечается после подготовки русской и английской версий, проверки HTML-примера в браузере и валидаторе, проверки нужного поведения клавиатуры, сборки, меню и поиска.

Для форм проверяются запрос и фактическое поведение учебного получателя. Для медиа проверяются локальные ресурсы и дорожки. Учебный прогресс читателя фиксируется отдельно; файлы статей и пункты меню добавляются по мере подготовки материалов.
